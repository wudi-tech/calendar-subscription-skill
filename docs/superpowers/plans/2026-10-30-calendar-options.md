# 日历来源与发布方式可选项

目标：保持现有单 JSON 生成与本地发布兼容，新增多来源合并和可选云端发布，二者可以组合。不在本次升级中切换真实订阅、发布个人日程或恢复暂停任务。

## 接口与实现

1. 新增 `build_calendar.py --manifest calendar.json --output study-plan.ics`：读取显式来源清单，支持原有 JSON 与现存 ICS。JSON 继续使用原 feed_id/id 派生身份；ICS 保留 UID、周期规则、例外、时区和提醒。冲突、缺失、无效来源和意外空输出都停止，验证后才写文件。
2. 清单中的来源路径以清单目录为根，只允许该目录内的相对路径。来源按单独责任人维护。每个 JSON 源有永久且唯一的 feed_id；同一 id 可以出现在不同命名空间中。
3. 扩展 `Publish-Feed.ps1` 增加与 InputPath 互斥的 ManifestPath；保留现有参数与发布保护。
4. 新增可复制的 GitHub Pages Actions 模板。显式变量开关启用，生成依赖和来源随仓库存放；构建失败不部署。不自动启用真实日历，且只将生成目录作为站点文件发布。
5. 新增独立 CI：在 Linux/Windows 检查生成、合并、发布和模板；云端生成合成示例验证 artifact。这里的 CI 不发布个人日历。
6. 更新技能入口、模式选择说明、迁移步骤、各对话源文件协作约定，以及版本验证记录。

## 验证顺序

先写并运行会失败的行为测试，再实现。验证多源同名 id、源更新不影响其他事件、稳定 UID、重复运行、取消、旧 ICS 周期/例外/提醒/时区、重复 UID、错误输入不覆盖、路径边界、单源兼容和多源本地发布。检查 workflow 的显式开关、权限、构建依赖和 artifact 路径，并在 GitHub 运行合成 CI。

只读使用现有真实 ICS 进行本地合并演练，比较事件身份与组件，不上传演练文件或个人数据。通过后提交并推送技能仓库，检查远端提交和 CI 结果。
