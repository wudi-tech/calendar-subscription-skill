完整测试先安装 `requirements-dev.txt`；多来源生产环境只需 skill 内的 `requirements-merge.txt`。**27 项本地测试通过**，包含：

| 范围 | 实际检查 |
|---|---|
| 时间和提醒 | 带偏移输入转换为 UTC，提前十分钟 VALARM |
| 文本格式 | 中文、转义、CRLF、UTF-8 字符边界、每行不超过 75 字节 |
| 身份和版本 | 改时间及标题仍保留 UID，输出显式版本与修改时间 |
| 取消 | 保留事件身份，输出 CANCELLED，不保留提醒 |
| 输入失败 | 无时区、时间倒置、无效版本、重复 ID、错误提醒和状态被拒绝 |
| 不支持的语义 | uid 覆盖、rrule 和全天字段明确报错，不静默忽略 |
| 文件写入 | 相同输入不重写，验证失败不覆盖，禁止输入输出同路径 |
| 发布 | 本地临时裸仓库模拟推送，目标内容可读取，无变化不新建提交 |
| 失败重试 | 上次已提交但未推送的 feed 可再次推送 |
| 变更隔离 | 拒绝脏工作区和包含无关文件的待推送提交 |
| Windows 换行 | `core.autocrlf=true` 时仍验证远端对象与本地 ICS 字节一致 |
| 默认行为 | 没有 `-Publish` 时只生成，不提交或推送 |
| 多来源 | 不同 feed_id 的同名事件共存；来源重排不改变输出；更新一个源不改变其他组件 |
| 旧 ICS | 保留 UID、周期、例外、时区、嵌套提醒和全天事件；重复回车仅在读取时规范化 |
| 合并失败 | 重复身份、时区冲突、缺源、来源路径越界、不支持的组件及全空输出停止 |
| 本机合并发布 | `-ManifestPath` 能发布完整合并结果，并与 `-InputPath` 互斥 |
| 云端模板 | 显式变量开关、默认分支、部署依赖构建、最小权限和独立 artifact 目录 |
| 云端构建命令 | 在模拟 checkout 执行模板同一生成命令；缺源时失败且不覆盖旧结果 |

发布集成测试只使用临时本地 Git 仓库。Windows 上实际运行了 PowerShell 脚本；缺少 PowerShell 的环境会跳过发布集成测试，不能把跳过称为已验证。

## 技能行为演练

独立评估者分别在没有新技能、读取技能后对虚构请求给出操作方案。基线方案已经正确区分发布与设备提醒，没有人为制造失败。带技能的演练检查了旧 UID 迁移、未授权公开会议密码、暂停任务和提醒承诺。

初版演练发现生成器最初会忽略未知字段，随后用失败测试复现并修复为显式拒绝。

选项升级又进行了独立静态复核：多来源保留旧 ICS 的路线成立；评估指出云端若上传 checkout 既有站点目录，可能混入其他文件。已补回归测试，并改为 runner 临时目录内按 run/attempt 隔离的输出。

## 现有文件本地兼容性演练

在临时目录复制原 ICS，与一条合成毕设事件合并，结果为 434 个事件组件。逐一比较解析后的原组件序列化结果，433 条旧事件和时区组件均保留；再次生成字节相同，真实源文件字节未改动。演练文件未上传到 GitHub，也未发布到实际订阅。

仓库另有 Linux/Windows、Python 3.10/3.14 的合成数据 CI，运行入口见 [Actions](https://github.com/wudi-tech/calendar-subscription-skill/actions)。该 CI 不部署用户日历；实际运行结论应以对应提交的 job 结果为准。

## 尚未验证及有意限制

- 没有修改真实订阅或在真实手机上测试通知；不能保证某个设备准时弹窗或响铃。
- 没有为本包注册 Windows 后台任务或 Codex 自动化。
- JSON 新建事件不支持全天、RRULE 或 RECURRENCE-ID；合并器可以保留既有 ICS 中的这些字段。不做旧 ICS 到 JSON 的自动迁移。
- 修改时间和版本由日程来源维护；发布器不会自动检测老师的通知或猜测变更。
- 发布脚本止于 Git push；Pages 正文比对和设备显示必须按接入文档另行完成。
- 未启用真实日历的 Actions 部署；合成 CI 不能代替 Pages 部署和设备验证。macOS 未实测；其他平台结果以对应 CI 日志为准。

GitHub 上发布的是本技能与合成示例，不是本次实际个人日程数据。
