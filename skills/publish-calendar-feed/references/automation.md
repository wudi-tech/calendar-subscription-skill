# 持续运行与触发器

生成器、发布器、定时触发器是三个独立部分。安装 skill 不会建立后台任务；创建定时任务也不会自动读取课程通知。先确认可靠的数据来源，再决定触发频率。

## 复用原来的任务

检查当前任务配置、状态、运行账户和最近日志。历史存在的配置可能已经暂停、文件已移动或计划时间段已过期。原学习日历的每天 08:00 Codex 自动化在 2026-10-30 核对时处于 PAUSED；本包没有重新启动它。

## Windows 路线

适用于源文件和 Git 凭证都在本机、电脑通常开机的情况。

1. 先用目标账户手动跑一次完整发布，确认 Git upstream 和认证可用，远程 ICS 与本地一致。
2. 在任务计划程序新建或修改已有任务：触发时间按用户时区设置；“启动程序”选 PowerShell 的绝对路径。
3. 参数采用 `-NoProfile -WindowStyle Hidden -ExecutionPolicy Bypass -File`，随后接发布脚本绝对路径，以及 `-InputPath`、`-PublishRepo`、可选 `-Python` 和明确授权后的 `-Publish`。路径含空格时用双引号。后台运行不需要可见终端。
4. “起始于”填写任务所在目录，但脚本参数仍使用绝对路径。设置已有实例运行时不再启动新实例；发布脚本本身也有文件锁。
5. 按需求启用错过触发后补跑，并明确睡眠、关机、网络不可用时的行为。不要假设系统能在关机时执行本地 Python。
6. “立即运行”一次，检查任务最后结果、Git 提交与实际 HTTPS feed。为生产任务加入按日期的成功/失败日志或任务历史；不要把包含凭证的命令、环境变量或个人课表记录进公开日志。

本例发布脚本不自行注册系统任务。若任务账户与交互账户不同，需要在该账户下验证 Git 凭证，不能通过在脚本中硬编码 token 来解决。

## Codex 自动化路线

当用户要求通过 Codex 定时维护时，先发现当前环境的 `automation_update` 工具并按其现行参数执行；先读取匹配配置，优先更新旧任务。不要硬编码历史工具参数、旧模型名称或自动化 ID。

此类本地发布通常需要能访问源文件和专用仓库的执行环境。按工具对项目任务与聊天跟进的现行规定选择任务类型。提示词应说明：读取哪个来源、运行哪个绝对路径、发布哪个 feed、如何核对远程版本，以及失败时停止并报告。

自动化的通知策略要保持用户本意；没有实质变化时保持安静，在完成、失败或需要用户操作时通知。不要用另一个更频繁的聊天提醒来替代手机日历订阅刷新。

## 可复用的执行要求

- 先校验输入，再写文件；校验失败不发布旧输出冒充新结果。
- 内容未改变时不新建提交；上次已提交但推送失败时允许重试推送。
- 无关改动、冲突、身份失效或分支拒绝时停止，不强推或无限重试。
- Git push 成功后仍检查 Pages；Pages 正确后仍需分别验证客户端显示与提醒。
- 取消定时服务时停用对应任务，不替用户删除订阅或历史日程。
